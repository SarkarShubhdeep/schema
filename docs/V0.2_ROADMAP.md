# v0.2 Roadmap

Integration branch: **`develop`**  
Release target: **0.2.0** (internal TestFlight on macOS)

Track shipped work in [CHANGELOG.md](../CHANGELOG.md) under `[Unreleased]`. Close or update items in [KNOWN_ISSUES.md](KNOWN_ISSUES.md) as they land.

## How to work

1. Branch off `develop`: `feature/*`, `fix/*`, or `enhancement/*`
2. Merge back into `develop` when a slice is done
3. Bump `CURRENT_PROJECT_VERSION` only when uploading a TestFlight build
4. Bump `MARKETING_VERSION` to `0.2` when cutting the release on `main`

## Priority order

Work top-to-bottom. Phase 0 is a prerequisite if any SwiftData model changes are planned.

---

### Phase 0 — Foundation (do first if models change)

**Branch:** `feature/swiftdata-migration`

| Item | Why |
|------|-----|
| Add `VersionedSchema` + `SchemaMigrationPlan` | v0.1 testers lose data on model changes without this |
| Replace `fatalError` on `ModelContainer` failure | Show recoverable error UI instead of crashing |

**Touch:** `SchemaApp.swift`, new `Schema/Core/Persistence/` files

---

### Phase 1 — Task descriptions

**Branch:** `feature/task-descriptions`

| Item | Detail |
|------|--------|
| Edit description in task row or detail | `SchemaTask.taskDescription` exists; UI is display-only today |
| Persist via existing SwiftData save path | Use `TaskViewModel.updateDescription()` |

**Touch:** `TaskRowView.swift`, `TaskViewModel.swift`, possibly `TaskListView.swift`

---

### Phase 2 — True manual sort (drag-to-reorder)

**Branch:** `feature/task-drag-reorder`

| Item | Detail |
|------|--------|
| Drag tasks to reorder when sort = Manual | Today "Manual" sorts by `createdAt` |
| Persist order on `SchemaTask` | Likely new `order: Int` field → **requires Phase 0 migration** |

**Touch:** `SchemaTask.swift`, `TaskViewModel.swift`, `TaskListView.swift`, `TaskRowView.swift`

---

### Phase 3 — List reordering

**Branch:** `enhancement/list-reorder`

| Item | Detail |
|------|--------|
| Wire `ListViewModel.reorderLists()` to UI | Method exists but is never called |
| Drag tabs or reorder in All Lists | `SchemaList.order` already exists |

**Touch:** `ListNavigationBar.swift`, `AllListsView.swift`, `ListViewModel.swift`

---

### Phase 4 — Reliability & polish

**Branch:** `enhancement/error-handling` / individual `fix/*`

| Item | Detail |
|------|--------|
| Surface save failures to the user | Today `assertionFailure` in debug only |
| Reminder scheduling error feedback | Settings / task row when permission denied |
| TestFlight feedback triage | Bugs filed by internal testers |

---

## Out of scope for v0.2 (unless you explicitly promote)

- iOS target or iOS TestFlight
- Mac App Store public listing
- XCTest / CI pipeline
- App Store name change (stays **Schema: Fast, Simple Todos**)

---

## Suggested first branch

If you are adding task descriptions **without** new model fields, start with:

```bash
git checkout develop
git pull origin develop
git checkout -b feature/task-descriptions
```

If drag-reorder or any new `@Model` property is in the first slice, start with **`feature/swiftdata-migration`** instead.

## Release checklist (when v0.2 is ready)
